# AppLock

**Временная блокировка приложений Windows паролем.**

AppLock помогает ограничить случайный доступ к выбранным программам, пока вы отошли от компьютера. Вы выбираете приложения, задаёте пароль на текущий сеанс и вручную включаете блокировку. После разблокировки приложения остаются доступны до следующего ручного включения.

**Windows 10 / 11 · C# · Windows Forms · .NET Framework 4.8 · Русский интерфейс**

[Скачать AppLock 3.0](releases/AppLock-3.0-Windows.zip) · [История изменений](CHANGELOG.md) · [Подробная инструкция](docs/USER-GUIDE.txt)

## Возможности

### Доступ к приложениям

- Блокировка выбранных `.exe` с паролем на один сеанс.
- Окно ввода пароля при попытке запуска заблокированного приложения.
- Разрешение одного приложения до полного закрытия или на **5, 15 или 30 минут**. Остальные приложения продолжают блокироваться.
- Смена пароля во время сеанса без отключения блокировки.
- Добавление через выбор файла, ярлык `.lnk`, открытые окна или список установленных программ.
- Поиск, галочки выбора и перетаскивание файлов в список.

### Настройки сеанса

- Наборы приложений с импортом и экспортом в `.applock`.
- Необязательный таймер снятия всей блокировки: от 1 до 1440 минут.
- Защита AppLock от обычного принудительного завершения во время активного сеанса.
- Скрытие названий приложений, тихий режим и сворачивание в трей.
- Журнал последних 500 событий с фильтрами и экспортом в текстовый файл.
- Пауза на 30 секунд после пяти неверных попыток ввода пароля.
- Кнопка блокировки рабочего стола Windows.

### Интерфейс

- Светлая и тёмная темы.
- Карточки с иконками, путями и состоянием доступа; переключение на таблицу.
- Сохранение настроек интерфейса, размера окна, списка приложений и наборов.
- Горячая клавиша `Ctrl + Alt + A` для открытия AppLock из трея.

## Как пользоваться

1. Запустите `AppLock.exe`.
2. Добавьте приложения и отметьте галочками нужные.
3. Сохраните работу и полностью закройте выбранные приложения, включая их фоновые процессы.
4. Нажмите **«Включить блокировку»** и дважды введите пароль от 6 символов.
5. При необходимости сверните AppLock в трей. Во время активного сеанса крестик окна также сворачивает программу в трей.
6. Чтобы закончить сеанс, нажмите **«Снять блокировку»** и введите пароль.

После этого блокировка остаётся выключенной. При следующем включении можно задать другой пароль. Автозапуска и автоматического восстановления сеанса после перезагрузки нет.

### Открыть только одно приложение

При заблокированном запуске появится окно пароля, если эта функция включена в настройках. Можно также нажать **«Доступ к приложению»** в AppLock или **«Разрешить…»** на видимой карточке.

| Режим | Когда доступ заканчивается |
| --- | --- |
| До полного закрытия | После завершения всех процессов выбранного `.exe`, включая фоновые; предусмотрена пауза 2 секунды между процессами |
| На 5 / 15 / 30 минут | По окончании срока приложение принудительно закрывается и снова блокируется |

Если в режиме «До полного закрытия» приложение не запустилось за 30 секунд, разрешение отменяется. После завершения всего сеанса все временные разрешения сбрасываются.

> **Сохраняйте работу заранее.** Заблокированные запуски и приложения с истёкшим разрешением на время закрываются принудительно, без сохранения данных. Общий таймер сеанса работает иначе: он снимает всю блокировку без пароля.

### Горячие клавиши

| Сочетание | Действие |
| --- | --- |
| `Ctrl + Alt + A` | Показать AppLock, пока он запущен; сочетание должно быть свободно |
| `Ctrl + F` | Поиск в списке AppLock |
| `Ctrl + O` | Добавить `.exe` или `.lnk` |
| `Delete` | Убрать выделенные строки в режиме таблицы при выключенной блокировке |

## Как работает блокировка

AppLock примерно каждые 150 мс проверяет процессы в текущем сеансе Windows и принудительно завершает выбранные приложения по полному пути к `.exe`. Это означает, что окно программы может успеть появиться до закрытия. Если разрешён доступ к отдельному приложению, оно временно исключается из блокировки.

При включении сеанса выбранные приложения должны быть закрыты. Если приложение продолжает работать в фоне, AppLock попросит закрыть его самостоятельно.

### Защита от завершения через диспетчер задач

Начиная с версии 2.1, AppLock может временно ограничивать право принудительного завершения собственного процесса. После снятия блокировки или окончания общего таймера исходные права восстанавливаются. Пункт **«Выйти»** в трее во время сеанса требует пароль.

Эта функция ограничивает обычное завершение. Администратор с соответствующими привилегиями может обойти её; программа, заранее получившая право завершения процесса, также может сохранить эту возможность. Перезагрузка и выход из Windows заканчивают сеанс.

AppLock остаётся видимым в списке процессов. Он не отключает диспетчер задач, не устанавливает службы или драйверы и не перезапускает себя после завершения.

### Границы защиты

- AppLock предназначен для ограничения случайного доступа на вашем компьютере. Он не защищает от администратора и не заменяет пароль учётной записи Windows.
- Правило относится к конкретному пути `.exe`. Копия программы по другому пути, другой исполняемый файл, веб-версия сервиса и прямой доступ к файлам остаются вне этого правила.
- Приложения с повышенными правами могут быть недоступны обычному процессу AppLock. В таком случае он показывает ошибку.
- Список установленных программ собирается из меню «Пуск» и App Paths. Он может не включать отдельные игры, переносимые программы и приложения Microsoft Store.
- Ярлыки поддерживаются, если указывают на локальный `.exe`. При повторном запуске через AppLock аргументы ярлыка, URL и документы не передаются; их нужно открыть снова.
- Пароль AppLock действует только на текущий сеанс. Для разблокировки рабочего стола после кнопки «Блокировать Windows» нужен пароль или PIN самой Windows.

## Пароль и локальные данные

Пароль не записывается на диск. Проверка использует производное значение PBKDF2-HMAC-SHA256 с отдельной случайной солью и 210 000 итераций в памяти. После окончания сеанса массивы соли и производного значения очищаются. Восстановления забытого пароля нет; перезапуск Windows завершает временный сеанс.

В `%LOCALAPPDATA%\AppLockSession` сохраняются:

| Файл | Содержимое |
| --- | --- |
| `selection.xml` | Пути приложений и состояния галочек |
| `profiles.xml` | Сохранённые наборы |
| `preferences.xml` | Тема, вид списка, размер окна и постоянные настройки |

Пути в этих файлах не зашифрованы. Пароль, активная блокировка, общий таймер и временные разрешения между запусками не сохраняются. Журнал находится в памяти и записывается в файл только при ручном экспорте. AppLock не отправляет данные по сети.

## Обновление и удаление

Для обновления закройте старую версию через трей, распакуйте новый архив и запустите новый EXE. Во время активного сеанса для штатного выхода потребуется пароль. Одновременно используйте одну версию AppLock.

Списки и наборы версий 2.0 и 2.1 совместимы с 3.0. Список первой версии из `applications.txt` читается, если ещё нет `selection.xml`; старый файл не удаляется.

Для удаления снимите блокировку, закройте AppLock и удалите распакованную папку программы. При желании отдельно удалите `%LOCALAPPDATA%\AppLockSession`, чтобы убрать сохранённые списки и настройки.

## Сборка из исходников

Исходники в `source/` относятся к **3.0**. Код предыдущих версий находится внутри соответствующих ZIP в `releases/`.

Сборка использует C# 5 и компилятор установленного .NET Framework. Visual Studio и загрузка внешних пакетов не требуются. Выполните в PowerShell из корня репозитория:

```powershell
.\source\build.ps1 -OutputDirectory .\build
```

Результат: `build\AppLock.exe` и `build\AppLock.exe.config`.

### Проверки

```powershell
.\source\tests\test.ps1 -OutputDirectory .\test-output
```

Тесты работают с отдельными тестовыми процессами и настройками. Для них нужен интерактивный сеанс Windows; во время проверки появляются тестовые окна. Проверки завершения процесса требуют среды, в которой разрешено завершать собственные тестовые процессы: общие ограничения среды могут повлиять на результат.
